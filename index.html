How this table is calculated, no scores invented. Single-model cost per finding is the observed cost from the verified 50-finding run for the 25 scored models (SCORED cpf), and for untested models it is estimated from their real per-token prices in ALL_MODELS at 155 prompt + 250 completion tokens, the observed mean token counts. Two-stage cost per finding is single-model cost plus 10 percent escalation times the selected Stage 2 cost per call, where the Stage 2 cost per call uses priceOf(byId(stage2Model)): observed $0.001597 per successful call for openai/gpt-6.1-sol, $0.000233 for google/gemini-3.5-flash-lite and $0.000634 for Qwen/Qwen3.8-Flash from the 5-finding smoke test at max_tokens 800, otherwise 155 prompt + 250 completion tokens at that model's real prices. Accuracy per dollar is accuracy divided by single-model cost per finding, scored models only. Untested models show cost only, with a clear UNTESTED label, no invented accuracy, no invented F1. Benefit is a judgement from the verified misses and unparsed counts, not a measured two-stage score: models with misses or unparsed findings could in principle gain from a second look, perfect models with no misses gain nothing except cost, and whether Stage 2 actually fixes a miss is unknown until a full 50-finding two-stage run. ● Methodology

How the benchmark was run

So anyone can check the setup before trusting the scores, and reproduce the run.

Dataset and prompt

  • Fixed dataset of 50 generic, public-style code snippets. 25 real vulnerabilities, 25 false positives. No private findings were used.
  • The categories are NOT balanced. 11 categories have 4 findings each: sql-injection, xss, ssrf, command-injection, hardcoded-secret, weak-crypto, insecure-deserialization, jwt, auth-bypass, idor, and sensitive-data. Three categories have 2 findings each: path-traversal, CSRF, and open-redirect. 11 x 4 + 3 x 2 = 50 findings in total.
  • Balanced v2 dataset: dataset-v2.json holds 56 findings, 14 categories x 4 each, 28 real and 28 false positives, adding S26, F26, S27, F27, S28 and F28 to balance path-traversal, csrf and open-redirect. v2 has NOT been run, no v2 results exist, and v1 results must not be treated as v2 results. Safe upper-bound cost to run v2 on the 4 original models is $0.67 total.
  • One label is contestable: F17, a JWT test that uses the mock secret 'test-secret', is labelled false positive because it is test code. A production reviewer could reasonably call it real, and GLM-5.3-Flash did. See the note on F17 in the Dataset viewer.
  • A finding counts as real only if untrusted input actually reaches a dangerous sink with no effective mitigation in the code shown.
  • The same prompt was used for every model. Each model had to return ONLY JSON, with a verdict of real or false_positive, plus severity and a reason.
  • Settings were identical for all models in the 2026-11-08 pass and Batch 1-A: temperature 0. The first pass used max_tokens 1000, the targeted re-run used 2500. A separate left-models run started 2026-11-09 13:14 UTC uses max_tokens 800 and a $10 actual-spend cap, and its scores are not merged here until they are verified.

Honest limitation

The dataset is deliberately clear-cut, so perfect scores mean these models handle clear-cut cases well. They do not prove the same score on subtle, real-world code, where the line between a real vulnerability and a false positive is much harder to draw. That is exactly what the Live Triage tab is for: test the models on your own code.

Test Key says "Network error". What is wrong?

The API itself is reachable and CORS-open, and it answers a bad key with an "Invalid API key (401)" message, so a network error is not your key. It means the browser was stopped before any answer came back. The GMI API sits behind Cloudflare, which can reject in-app browsers and webviews by their browser signature, and a VPN, a content blocker, or a dropped mobile connection causes the same failure. Test Key and Live Triage retry once automatically and time out cleanly instead of spinning. If it still fails, open this page in a full browser (Chrome or Safari, not an in-app viewer), turn off any VPN or blocker, and try again.

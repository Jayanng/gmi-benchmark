● Repo audit

Audit a whole repo, file by file

Paste files, fetch a public GitHub repo, or upload a zip. Pick the checks you care about, pick a model, and each file is audited on its own. A finding is only reported if the model finds it in the code shown: nothing is invented, and a file with no findings says so plainly.

1 · Bring the code

Limits, stated up front: at most 10 files per run, at most 40 KB per file, 200 KB total. Larger files are skipped and listed as skipped. GitHub fetch works for public repos only, unauthenticated, so GitHub allows about 60 requests an hour from your browser. Private repos are not supported here: paste their files instead.

Code files only: .py .js .ts .jsx .tsx .go .java .php .rb .rs .c .h .cpp .cs .kt .swift. Folders like node_modules, vendor, dist and .git are skipped.

    The zip is read in your browser only, it is never uploaded to us. Same limits: 10 files, 40 KB per file, 200 KB total. If the zip reader fails to load, paste the files instead.

      How the audit prompt works

      • The same prompt is sent for every model and every finding, at temperature 0, so the only thing that changes is the model and the code you paste.
      • A finding counts as real only if untrusted input actually reaches a dangerous sink with no effective mitigation in the code shown.
      • If the code uses parameterisation, escaping, allowlists, or another effective mitigation, the verdict is false positive.
      • The model must return only JSON: verdict, severity, confidence, reason, and a suggested fix. If it does not, the page says unparsed instead of guessing a verdict.
      • Repo audit uses the same rule, one file at a time, and only for the checks you ticked.

      Check it yourself

      • Methodology in the repo README: dataset, prompt, and how the test set was run.
      • dataset.json in the repo: all 50 findings, labels, code, and explanations.
      • Source on GitHub: the full project, including the per-finding results files kept as evidence in the repo, not shown here.
      • One label in the test set is contestable: F17, a JWT test with a mock secret, is labelled false positive because it is test code. In production auth it would be real.

      Honest limitation

      The test set is deliberately clear-cut, so a model doing well on it only shows it handles clear-cut cases. It does not prove the same on subtle, real-world code, where the line between a real vulnerability and a false positive is much harder to draw. That is exactly what the audit tool above is for: test the models on your own real findings before relying on one.

      # The exact audit prompt sent with every finding You are a security code reviewer. Classify this finding. A finding is real only if untrusted input actually reaches a dangerous sink with no effective mitigation in the code shown. If the code uses parameterisation, escaping, allowlists, or other effective mitigation, it is a false_positive. Return ONLY JSON, no other text: {"verdict": "real" or "false_positive", "severity": "critical|high|medium|low", "confidence": 0-1, "reason": "one short sentence", "fix": "one short sentence"}

      ● Questions

      Before you run anything

      Is my API key safe on this page?

      Your key stays in your browser. It is kept in sessionStorage for this tab only, never in long-term browser storage, never logged, and the only request it is ever attached to goes directly from your browser to https://api.gmi-serving.com/v1. Press Clear key, or close the tab, and it is gone. Test Key calls GET /v1/models only, it does not run a chat call and costs nothing. This page loads Google Fonts, which sends your IP address to Google; there is no other analytics, no cookies, and no key logging on this page.

      What does an audit cost?

      Your GMI account is charged per token, at the model real per-token prices. The estimate under the model picker shows a typical cost and a maximum cost before you run, from your input length and the max_tokens setting. Typical costs are a fraction of a cent per finding for most models. We spend $0: this page has no server and makes no calls of its own.

      Does a verdict mean my code is safe?

      No. A verdict is one model reading on the code you showed it. It can be wrong, it can miss things, and it only sees the code you pasted. Read the reason, check the code yourself, and treat the report as a starting point for a fix, not as proof.

      Test Key says "Network error". What is wrong?

      The API itself is reachable and CORS-open, and it answers a bad key with an "Invalid API key (401)" message, so a network error is not your key. It means the browser was stopped before any answer came back. The GMI API sits behind Cloudflare, which can reject in-app browsers and webviews by their browser signature, and a VPN, a content blocker, or a dropped mobile connection causes the same failure. Test Key and the audit retry once automatically and time out cleanly instead of spinning. If it still fails, open this page in a full browser (Chrome or Safari, not an in-app viewer), turn off any VPN or blocker, and try again.
